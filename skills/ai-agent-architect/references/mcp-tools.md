# MCP servers and agent tools

Determine the exact capability, client/runtime, data sources, read/write actions, deployment constraints, and authentication needs before searching. Check existing integrations and native APIs as well as MCP; an MCP server is not automatically the best choice.

For discovery, consult the [MCP registry](https://github.com/modelcontextprotocol/registry), service provider documentation, and candidate repositories. A registry entry is a discovery lead, not a security endorsement. Confirm the identity of the publisher and distinguish provider-maintained, community, and reference implementations.

Compare viable candidates against the task: supported operations and transport, client compatibility, authentication and permission scope, data handling, local or hosted deployment, dependencies, maintenance and release activity, license, cost, and documented limitations. Inspect available schemas and source or documentation when relevant; look for side effects, arbitrary command execution, broad access, prompt-injection exposure, and supply-chain concerns. Mark unavailable evidence as unknown rather than assuming safety or quality.

Give a recommendation and meaningful alternatives with direct evidence links and a proportionate validation plan. Distinguish documentation-based assessment from actual testing. Do not execute discovered install commands, connect accounts, grant permissions, or modify configuration without authorization.
