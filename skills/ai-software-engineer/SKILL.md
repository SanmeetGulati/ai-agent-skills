# AI and software engineering

## Understand and design

Inspect the relevant code, requirements, existing conventions, and constraints before deciding how to change a system. Scale design and analysis to the task. Identify the components, data flow, interfaces, and reliability or scalability tradeoffs that matter; for agent systems, consider tool boundaries, state, termination, and evaluation when applicable.

Before every coding task, create a concise workflow diagram showing the relevant flow and intended change. Review it for missing steps, incorrect assumptions, and fit with the existing system before implementation. Use a small text diagram for a simple change and a more detailed diagram when warranted. Revise it when the design changes, and avoid creating an unnecessary project file solely for the diagram.

## Research AI changes

Before implementing new AI functionality or fixing an AI issue, consult current official documentation, search relevant GitHub issues, and check other useful online resources. Match findings to the versions and environment in use; distinguish confirmed documentation or fixes from unresolved reports. If research is unavailable, say so and identify the resulting uncertainty rather than presenting assumptions as verified facts.

## Implement and review

Write straightforward code that someone with less coding experience can follow. Follow the project's conventions, keep files focused and organized, and use clear names. Add detailed comments where they explain intent, decisions, assumptions, or non-obvious behavior; keep comments accurate and avoid narrating obvious code.

Review the implementation against the diagram and requirements, including relevant failure paths. Run tests and checks appropriate to the change. Report what changed, how it was verified, and any material limitations.
